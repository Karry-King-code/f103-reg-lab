## 2. 寄存器版工程和另两个仓库差在哪（本章核心知识点）

```
标准库版: main.c → SPL 函数(GPIO_Init) → 封装内部写寄存器 → 硬件
HAL  版: main.c → HAL 函数(HAL_GPIO_Init) → 封装(更厚) → 硬件
寄存器版: main.c → 直接写 GPIOC->CRH 等寄存器 → 硬件
```

本仓库 `User/main.c` 之外**没有任何外设驱动 .c**——对比：

| | 标准库 | HAL | 寄存器 |
|---|---|---|---|
| 外设驱动 .c 文件 | rcc/gpio/misc（按需加） | 全量 HAL（链接器裁剪） | **0 个** |
| 头文件体系 | stm32f10x.h + conf.h | stm32f1xx.h + hal_conf.h | **仅 stm32f10x.h** |
| 工程宏 | `USE_STDPERIPH_DRIVER,STM32F10X_MD` | `USE_HAL_DRIVER,STM32F103xB` | **只留 `STM32F10X_MD`** |
| 编译产物（空工程） | Code=852B | Code=1838B | Code=852B |

**知识点：没有库 ≠ 没有头文件。** `stm32f10x.h` 是 ST 官方 **CMSIS 设备头文件**，它不"干活"，只干一件事：**把芯片手册里的每个寄存器变成 C 结构体**。例如：

```c
#define PERIPH_BASE           0x40000000UL
#define APB2PERIPH_BASE       (PERIPH_BASE + 0x10000UL)
#define GPIOC_BASE            (APB2PERIPH_BASE + 0x1100UL)   /* GPIOC 在 0x40011000 */

typedef struct {
  __IO uint32_t CRL;    /* 偏移 0x00: 低 8 脚配置 */
  __IO uint32_t CRH;    /* 偏移 0x04: 高 8 脚配置 */
  __IO uint32_t IDR;    /* 偏移 0x08: 输入数据 */
  __IO uint32_t ODR;    /* 偏移 0x0C: 输出数据 */
  __IO uint32_t BSRR;   /* 偏移 0x10: 原子置位/复位 */
  __IO uint32_t BRR;    /* 偏移 0x14: 原子复位 */
  __IO uint32_t LCKR;   /* 偏移 0x18: 锁定 */
} GPIO_TypeDef;

#define GPIOC               ((GPIO_TypeDef *) GPIOC_BASE)
```

于是 `GPIOC->ODR = 0x2000;` 就是一条"往地址 0x4001100C 写 1"的 C 语句——**寄存器编程的本质：按芯片手册的地址和位定义读写内存**。这些结构体定义全部来自芯片手册的 memory map，不是我们编的，可以在 `stm32f10x.h` 里逐行核对（02 章点灯就带着核对一遍 GPIOC/RCC）。

**知识点：为什么 `__IO`？** `#define __IO volatile`。告诉编译器"这个地址的值随时会被硬件改变，禁止优化缓存它的读写"。没有 volatile，`while(GPIOA->IDR & 1)` 这种等待语句会被优化成死循环。

## 4. 编译与烧录

打开 `MDK-ARM/f103-reg-lab.uvprojx`，F7。预期：

```
Program Size: Code=852 RO-data=268 RW-data=20 ZI-data=1636
".\Objects\f103-reg-lab.axf" - 0 Error(s), 0 Warning(s).
```

烧录：

```
STM32_Programmer_CLI -c port=SWD -w .\Objects\f103-reg-lab.hex -v -rst
```

空主循环无现象，链路打通即可（与另两个仓库一致）。

**知识点：为什么脚手架的 Code 和标准库一样大（852B）？** 因为两者此刻都只包含启动文件 + SystemInit + 空主循环——SPL 的 .c 虽在工程里，但没被调用就不会链入。真正拉开差距在 02 章：点灯后标准库版会多出 `GPIO_Init/RCC_APB2PeriphClockCmd` 的代码量，寄存器版只多几条指令。

## 5. 工程结构逐文件讲

```
f103-reg-lab/
├─ User/
│  ├─ main.c               # 寄存器代码主战场（02 章开始写 RCC->APB2ENR 这类语句）
│  ├─ stm32f10x_it.c/.h    # 中断服务函数（寄存器版中断同样写在这里，函数名对齐向量表）
├─ Libraries/CMSIS/CM3/
│  ├─ CoreSupport/         # core_cm3.c/h：内核寄存器（NVIC/SysTick/SCB）
│  └─ DeviceSupport/ST/STM32F10x/
│     ├─ stm32f10x.h       # ★ 全部外设寄存器结构体与位定义（本仓库唯一的"库"）
│     ├─ system_stm32f10x.c# SystemInit()
│     └─ startup_stm32f10x_md.s  # 启动文件（与标准库仓库同一份官方文件）
└─ MDK-ARM/f103-reg-lab.uvprojx
```

**知识点：宏只剩一个。** 没有 `USE_STDPERIPH_DRIVER`（不引 conf.h），只留 `STM32F10X_MD`——它依然必要，因为 `stm32f10x.h` 内部要用它决定"中密度芯片有哪些外设"（C8T6 没有 FSMC/SDIO/TIM5~8 等，宏不对会在操作寄存器时踩到不存在的地址）。

## 6. 上电到 main()（三仓库同一链路）

```
复位 → 0x08000000 向量表 → Reset_Handler
     → SystemInit()（HSI 8MHz 安全起跑）
     → __main（搬 RW/清 ZI）→ main()
```

三个仓库的启动链路完全相同（用的是同一份 ST 官方启动文件与 SystemInit）——**芯片不管你用什么库**，库只是 main() 之后的分叉。这也是三条线能"同一功能三实现"的根基。
